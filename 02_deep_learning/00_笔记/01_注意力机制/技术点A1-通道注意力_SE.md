# A1 通道注意力（Squeeze-and-Excitation, SE）

> **一句话**：让网络自己算出一个 0~1 的权重向量，按列去缩放输入特征。

| 属性 | 值 |
| :--- | :--- |
| 来源 | Hu, Shen, Sun. *Squeeze-and-Excitation Networks*. CVPR 2018 |
| 作用粒度 | 按特征列（channel） |
| 参数量 | 约 `2C²/r`（C 为列数，r 为压缩比，常用 8 或 16） |
| 实现长度 | 约 12 行 |
| 恒等起点 | ❌ 不保证（见第 5 节） |

---

## 1. 解决什么问题

**痛点**：一维输入有几十上百列特征，但网络不知道哪几列是噪音、哪几列是关键。它只能一视同仁地全连上去，让权重慢慢学。

SE 的做法是**先显式算一个"每列有多重要"的分数**，再乘回去。相当于给网络加了一条捷径：不用靠庞大的全连接层去隐式地学这件事。

## 2. 机制（不用公式）

三步，名字就是它的做法：

**Squeeze（压缩）** —— 把每列的信息浓缩成一个数。图像上是"对每个通道做全局平均池化"，即把一张特征图压成一个数。

> ⚠️ **在纯向量输入上是恒等操作**：如果输入已经是 `[B, C]`，每列就只有一个数，"压缩"没事可做。照抄图像代码时多写一个 `AdaptiveAvgPool` 是多余的，还会把形状搞错。这是最常见的照搬错误。

**Excitation（激励）** —— 用一个小 MLP 从 C 维算回 C 维：`C → C/r → C`，中间夹 ReLU，最后 sigmoid 压到 0~1。这一步让各列**互相参照**（某列的分数取决于所有列），所以不是简单的按列缩放。

**Scale（重标定）** —— 逐列相乘：`out[:, i] = x[:, i] × w[i]`。

一句话总结：**看全局 → 给每列打分 → 乘回去**。

## 3. 形状怎么变

输入 `[B, C]`：

| 阶段 | 形状 | 说明 |
| :--- | :--- | :--- |
| 输入 | `[B, C]` | B 条样本，每条 C 个特征 |
| 压缩 | `[B, C]` | 向量输入下等于输入本身 |
| 降维 | `[B, C/r]` | 瓶颈层，参数主要省在这里 |
| 升维 | `[B, C]` | 回到原维度 |
| 门控 | `[B, C]` | 每个值在 0~1 |
| 输出 | `[B, C]` | 输入 × 门控 |

注意：**形状全程不变**，变的只是数值。所以 SE 可以插在任意位置，不改动下游代码。

## 4. 最小实现

完整可跑版（含 `__main__` 自检与 10 条测试）在 [`../../01_代码/04_通道注意力_SE/`](../../01_代码/04_通道注意力_SE/)。下面摘录核心部分：

```python
import torch
import torch.nn as nn

class SE1D(nn.Module):
    """一维特征上的通道注意力。输入 [B, C]，输出 [B, C] 与门控 [B, C]。"""

    def __init__(self, n_features, reduction=8):
        super().__init__()
        hidden = max(1, n_features // reduction)
        self.gate = nn.Sequential(
            nn.Linear(n_features, hidden),
            nn.ReLU(inplace=True),
            nn.Linear(hidden, n_features),
            nn.Sigmoid(),
        )

    def forward(self, x):
        w = self.gate(x)          # [B, C]，值域 (0, 1)
        return x * w, w


if __name__ == "__main__":
    x = torch.randn(4, 16)
    se = SE1D(16, reduction=4)
    out, w = se(x)
    print("输出形状:", tuple(out.shape))
    print("门控范围: %.3f ~ %.3f" % (w.min().item(), w.max().item()))
    print("参数量:", sum(p.numel() for p in se.parameters()))
```

跑一遍应该看到：输出 `(4, 16)`，门控在 0.x 附近，参数量 148。

**动手验证理解**：把 `reduction=4` 改成 `reduction=1` 再跑，参数量会涨到 544。这一步能让你直观看到"瓶颈层省了多少参数"。

## 5. 变体与对比

| 变体 | 差别 | 什么时候用 |
| :--- | :--- | :--- |
| **cSE**（原版） | 上面这种，全连接瓶颈 | 默认 |
| **sSE** | 不降维，直接 `C → C` | 列数很少（<16）时，降维会损失太多 |
| **ECA-Net** | 用一个一维卷积代替两层全连接 | 想进一步减参数，且列数很大 |
| **CBAM** | SE + 空间注意力串起来（即 A2） | 输入还有"位置"结构时 |

**与分组注意力（A7）的差别**：SE 只到**列级**——它能说"第 3 列重要"，不能说"导数量这一类整体重要"。若输入天然有语义分组，SE 会把这个结构打散。这是选 SE 还是选 A7 的唯一判断点。

### ⚠️ SE 不保证恒等起点

`sigmoid(0) = 0.5`，所以默认初始化的 SE 会把输入**整体缩小一半**，训练起点就已经偏离原网络。这意味着：加了 SE 之后如果效果变差，你无法立刻分清是"SE 没用"还是"初始缩放把训练搞坏了"。

若要做干净的对照实验，需要手工造恒等起点：把 `gate` 最后一层的 bias 设成一个大正数（如 `+5`），让 `sigmoid ≈ 0.993`。或者改用 A7 那种 `gate = 1 + γ·tanh(·)` 且末层零初始化的写法。**这一点在论文里通常被忽略，但影响对照实验的可解释性。**

## 6. 何时用 / 何时别用

**用**：
- 一维特征列数在 16~500 之间，不知道哪些列重要
- 想用最小代价先试一下"注意力有没有用"（12 行、参数少、几乎不影响训练速度）

**别用**：
- 列数少于 8 —— 降维后瓶颈太窄，收益不明显，参数量占比反而变高
- 输入有明确语义分组 —— 用 A7，SE 会把分组结构抹平
- 需要严格的"加前加后对照" —— SE 破坏恒等起点，改用 A7 或手工造恒等初始化
