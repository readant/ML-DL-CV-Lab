# A4 交叉注意力（Cross-Attention）

> **一句话**：用一路信息去"查询"另一路信息，挑出相关部分取回来。

| 属性 | 值 |
| :--- | :--- |
| 来源 | Vaswani et al. *Attention Is All You Need*. NeurIPS 2017（decoder 里的 encoder-decoder attention） |
| 作用粒度 | 单元与单元之间（需要多个单元才有效，见第 2 节警告） |
| 参数量 | 约 `4·d²` |
| 实现长度 | 约 20 行 |
| 恒等起点 | ❌ 不保证（有残差，但不等于恒等） |

---

## 1. 解决什么问题

**痛点**：有两路信息，需要**有选择地**融合。"全部拼接"会让网络自己去学该关注哪部分，参数浪费且难收敛。

交叉注意力的思路是：让 A 路提出**问题**（query），B 路提供**候选答案**（key 和 value），算一算哪个答案最相关，加权取回来。

## 2. 机制（不用公式）

三个角色，用图书馆打比方：

| 符号 | 直觉 | 来自哪路 |
| :--- | :--- | :--- |
| **Q**（Query，查询） | 我想找什么 | A 路 |
| **K**（Key，键） | 每个条目"讲什么"的标签 | B 路 |
| **V**（Value，值） | 每个条目"实际内容" | B 路 |

流程：`Q` 和每个 `K` 算相似度 → 归一化成权重 → 用权重加权求和 `V`。

### ⚠️ 单向量输入下它会退化

如果 Q 只有 1 个、K 只有 1 个（即输入是 `[B, d]` 而不是 `[B, N, d]`），
相似度只有一个数，归一化后权重恒等于 1，**注意力完全不起作用**，退化成一次普通的线性变换。

这是最常见的误用：把两个向量送进交叉注意力，以为在做融合，其实什么也没做。

**要让它有效，某一路必须先拆成多个单元**：可以是序列、可以是切分成多组、也可以是多个特征子空间。
A7 分组注意力把输入切成 4 组当 token，正是为了解决这个问题。

## 3. 形状怎么变

| 张量 | 形状 | 说明 |
| :--- | :--- | :--- |
| `q_in`（A 路） | `[B, Nq, d_q]` | Nq 个查询单元 |
| `kv_in`（B 路） | `[B, Nk, d_kv]` | Nk 个候选单元 |
| `Q` / `K` / `V` | `[B, Nq, m]` / `[B, Nk, m]` / `[B, Nk, m]` | 投影到同一维度 m |
| 相似度矩阵 | `[B, Nq, Nk]` | 每个查询对每个候选的分数 |
| 权重 | `[B, Nq, Nk]` | 沿最后一维 softmax，每行和为 1 |
| 输出 | `[B, Nq, d_q]` | 与 Q 同形状，便于残差相加 |

输出的**单元数跟着 Q 走**，与 K/V 的单元数无关。这一点决定了它用在哪儿：
想让 A 保持自己的长度、只是把 B 的信息吸进来，就用这个。

## 4. 最小实现

完整可跑版（含 `__main__` 退化演示与 10 条测试）在 [`../../01_代码/05_交叉注意力/`](../../01_代码/05_交叉注意力/)。下面摘录核心部分：

```python
import torch
import torch.nn as nn

class CrossAttention(nn.Module):
    """q_in: [B, Nq, d_q]，kv_in: [B, Nk, d_kv]，输出 [B, Nq, d_q]。"""

    def __init__(self, d_q, d_kv, d_model=32, dropout=0.0):
        super().__init__()
        self.q = nn.Linear(d_q, d_model)
        self.k = nn.Linear(d_kv, d_model)
        self.v = nn.Linear(d_kv, d_model)
        self.o = nn.Linear(d_model, d_q)
        self.scale = d_model ** -0.5
        self.drop = nn.Dropout(dropout)

    def forward(self, q_in, kv_in, return_weights=False):
        Q = self.q(q_in)                                  # [B, Nq, m]
        K = self.k(kv_in)                                 # [B, Nk, m]
        V = self.v(kv_in)                                 # [B, Nk, m]
        score = Q @ K.transpose(-1, -2) * self.scale      # [B, Nq, Nk]
        w = torch.softmax(score, dim=-1)
        out = self.o(self.drop(w @ V))                    # [B, Nq, d_q]
        return (out, w) if return_weights else out


if __name__ == "__main__":
    ca = CrossAttention(d_q=8, d_kv=5, d_model=16)

    q = torch.randn(2, 4, 8)     # 4 个查询单元
    kv = torch.randn(2, 6, 5)    # 6 个候选单元
    out, w = ca(q, kv, return_weights=True)
    print("正常情况  输出:", tuple(out.shape), " 权重:", tuple(w.shape),
          " 行和:", [round(float(v), 3) for v in w[0].sum(-1)])

    q1, kv1 = torch.randn(2, 1, 8), torch.randn(2, 1, 5)
    _, w1 = ca(q1, kv1, return_weights=True)
    print("单向量情况 权重:", w1.flatten().tolist(), "← 恒为 1，注意力失效")
```

**动手验证理解**：把 `Nq` 从 4 改成 1，同时 `Nk` 保持 6。权重会变成一个 `[1, 6]` 的分布（仍然有效），
说明只要有**多个候选**，即使只有一个查询，注意力依然在工作。真正失效的是"Nq 和 Nk 都为 1"。

## 5. 变体与对比

| 变体 | 差别 | 什么时候用 |
| :--- | :--- | :--- |
| **单头**（本文） | 一组 Q/K/V | 教学、小规模、快速验证 |
| **多头** | 并行若干组，各自关注不同子空间 | 实际使用，几乎总比单头好 |
| **自注意力**（A3） | Q/K/V 都来自同一路 | 单元之间互相参照，不是两路融合 |
| **分组注意力**（A7） | 把一路切成固定几组当 token，组间做注意力 | 单路输入、但内部有语义分组 |
| **线性注意力** | 用核函数替代 softmax，复杂度从 `N²` 降到 `N` | N 很大（>1000）时才值得 |

**与 FiLM（A5）的取舍**：FiLM 让条件只做"整体放大缩小"，参数量小一个数量级；交叉注意力能做逐单元的精细匹配，但要求输入有多单元结构。**如果两路都是单向量，交叉注意力会退化，此时应选 FiLM。**

## 6. 何时用 / 何时别用

**用**：
- 有两路信息，且**至少一路是多单元**（序列、多组、多位置）
- 需要"按内容动态选择"而不是"整体缩放"
- 输出要跟 A 路同长度（因为输出单元数跟着 Q 走）

**别用**：
- 两路都是单向量 —— 会退化成线性变换，白加参数
- 只需要整体调制 —— 用 A5 FiLM，更轻更快
- 单元数很多（>1000）—— 相似度矩阵是 `N²`，显存和时间都会爆，改用线性注意力
