# 分组注意力（Group Attention）

> 这是一份**算法实现**，不是某个项目的模块。
> 它不认识「电池」「SOH」「PINN」，也不知道组数一定是 4、某组一定是 17 维。
> 具体任务的维度配置属于**调用方**，见第五节。

| | 算法实现整理 | 项目工程重构 |

因此本目录的三条设计约束：

1. **算法本体零领域常量。** `group_dims` 是构造参数，取值 `(17,1,16,1)` 只出现在 demo 和文档里。
2. **测试不含项目配置。** 用 `(3,5,2)`、`(4,4)` 等任意分组验证，若某条测试只能靠 35 维的特定切分通过，说明算法里混进了领域假设。
3. **项目用法只作为「一份配置」出现**，且以文档形式陈述，不写成代码分支。

## 二、机制

输入是若干组特征张量（各组列数可不同）：

1. 每组经独立线性投影 → 一个 `d_model` 维 token
2. 全部 token 做多头自注意力 → 组间交换信息
3. 每个 token 生成标量门控 `gᵢ`（组内中心化，均值和恒为 1）
4. 用 `gᵢ` 缩放第 i 组特征

与「逐维通道注意力」（如 SE-Net）的差别：逐维门控只能回答「第 k 个特征多重要」；
分组门控回答「这一类量整体该被放大还是压低」。当输入天然带有语义分组时，后者的结论可解释。

`GroupGatedNet` 是它的通用包装：把任意 `nn.Module` 套上一层，对外接口不变，可原位替换。

## 三、三条硬约束（每条对应测试）

### 3.1 恒等初始化

`gate_head` 零初始化 → `tanh(0)=0` → `gᵢ ≡ 1`。训练起点对输入是**严格恒等变换**
（实测与同权重原网络逐元素差 `0.000e+00`）。

意义：加与不加的差别**全部**来自训练中学到的偏离量，使「该模块是否有效」成为可证伪的问题。

**前提**：恒等严格成立于 `eval()` 模式。主干含 Dropout，train 模式下即使 `gate=1`，
单次前向也与原网络不同。测试里用一条反证（`test_train_mode_differs_due_to_dropout`）钉住这一点，
避免以后误把 dropout 关掉还宣称恒等。

### 3.2 预算守恒（第一次真实失败）

初版写成 `gate = 1 + γ·tanh(·)`，实测各组门控**同步**下降：

```
step 100  gate=[0.815, 0.809, 0.796, 0.818]
step 600  gate=[0.856, 0.879, 0.840, 0.904]
```

全部朝同一方向 —— 这不是注意力，是**整体缩放**，等价于偷偷改学习率，对解释性毫无贡献。

改为组内中心化后：

```python
raw      = tanh(gate_head(attn_out))
centered = raw - raw.mean(dim=1, keepdim=True)   # Σ(gᵢ − 1) ≡ 0
gate     = 1.0 + γ · centered                    # 总预算固定，只做相对分配
```

合成任务（只有第 2 组带信息）的实测：

```
step 100  gate=[0.880, 1.236, 0.885]
step 600  gate=[0.954, 1.074, 0.973]
```

带信息那组被抬高、另两组被压低。**这才叫注意力。**

### 3.3 幅度受限（第二次真实失败）

`γ=1` 时 `gate ∈ (0,2)`，权重饱和会让 `tanh` 返回精确 `-1.0`，gate 变成 **0.0** ——
某一组被整组清零。若被清零的是关键分组，对应损失项直接静默失效，
而训练 loss 不会有任何异常提示。

现取 `γ = 0.25`，`centered ∈ (−2, 2)` → `gate ∈ (0.5, 1.5)`；`gate_scale ≥ 0.5` 直接 `ValueError`。

原则：**门控只能是微调，不能是开关。**

## 五、应用示例：一份具体配置

以下是**调用方**的事，算法本身不涉及。以 PINN4SOH 的 `dynamical_F` 输入为例：

```python
net   = 你的 dynamical_F 主干
gated = GroupGatedNet(net, (17, 1, 16, 1))
out   = gated(z)      # z 宽度必须为 35
```

这 35 维的切分依据（已实证，非推断）：

| 段 | 维数 | 含义 |
| :--- | :--- | :--- |
| `xt` | 17 | 15 个传感器特征 + `cycle index` |
| `u` | 1 | 解网络输出的 SOH |
| `u_x` | 16 | u 对 xt 前 16 维的梯度 |
| `u_t` | 1 | u 对 `cycle index` 的梯度 |

来源：CSV 原始 17 列（15 特征 + capacity）→ dataloader 在 capacity 前插入 `cycle index`
→ `x = df[:, :-1]` 得 17 维 → `forward()` 中 `x = xt[:,:-1]`（16）、`t = xt[:,-1:]`（1）
→ 拼接 `[xt, u, u_x, u_t]` = 17+1+16+1 = **35**，与 `input_dim=35` 吻合。

> 早期把这段说成「17 维特征 + 1 维 cycle index」是重复计数，会构造出 37 维输入。
> 该错误已由 `PINN4SOH` 侧代码与本仓库 demo 的双向核对排除。

## 六、局限

1. **未在真实任务上验证。** 本目录只证明算法正确、可学、不破坏原有网络，
   不证明在具体数据集上更准。后者必须回到真实数据做对照实验。
   → **已补：见 6.1（2026-11-09），结论是未测出收益。**
2. 合成任务里非目标组为纯噪声，与真实数据的信息分布差异很大，demo 的门控数值不可外推。
3. 门控幅度受限于 (0.5, 1.5)，表达能力有上限。若任务需要更强的重分配，
   应改用跨网络调制（用一路的隐状态去调另一路的中间层），而非放宽 γ。
4. 组数越多，token 序列越长，`MultiheadAttention` 的参数量按 `d_model²` 增长而与组数无关；
   组数很少（如 2 组）时组间注意力信息量有限，收益可能不如直接做逐维门控。

### 6.1 真实数据验证结果（2026-11-09 补记）

上面第 1 条局限已经有答案：本算法已在 nc-PINN 上完成两轮真实数据验证，**未测出收益**。

| 轮次 | 配置 | 关键结果 |
| :--- | :--- | :--- |
| 1103 | XJTU 2C，5 种子配对，A/B/C 三组对照 | A 原样 0.009452±0.001340；B 加门控 0.009531；C 等参数量随机门控 0.009553。**B−A = +0.000079（0.06σ_A），p = 0.6410** |
| 1108 | 同上，但先过机制门禁再谈性能 | M1 方差贡献 15.29%（边缘通过），**M2 / M3 / M4 未通过**；三组描述性 RMSE 差异 ≤ 0.00015（约 0.11σ_A） |

**三条结论**：

1. **门控未引入新信息。** 条件量取自 `dynamical_F` 的同一批输入（xt / u / u_x / u_t），
   本质是对已有信息做一次受限线性重参数化，网络第一层本就能吸收这类变换。
2. **B ≈ C 比 p 值更有信息量。** 等参数量随机门控（C）与训练过的门控（B）几乎相同，
   且两者距离小于各自与基线的距离——说明这个开关加不加，结果不变。
3. **两轮效应量都小于检测下限。** 种子标准差 σ_A = 0.001340，5 种子配对下检测下限约 1.93σ_A，
   即**小于约 26% 的相对改善在本设计下无法被证实**。本次差异约 0.06σ_A / 0.11σ_A，属于噪声量级。

**表述边界（重要）**：

- ✅ 可以写：本算法在 nc-PINN 当前配置下**尚未证实有效，适用条件未满足**。
- ❌ 不能写：「无效」「门控容量不足」「标准化无效」。
  1108 的 M2 / M3 / M4 未通过，说明瓶颈可能仍在实现侧（外层 `tanh` 饱和、`fc2` 偏置），
  通道是否被真正检验尚未定论。
